# Operation Black Tide
*A Living Special Operations Campaign Framework for Arma Reforger*

---

# Mission Statement

Our goal is not to build another Arma mission.

Our goal is to build a living Special Operations campaign framework that creates memorable stories through dynamic systems instead of scripted events.

Players should feel like a small, highly capable special operations team operating deep behind enemy lines inside a much larger war.

The world should feel alive.

The war should continue whether players are present or not.

The players are not the army.

They are the force multiplier.

---

# The Core Fantasy

Most Arma servers ask players to become the frontline.

This project does not.

Players perform missions that conventional forces cannot.

Examples include:

- Destroying enemy radar
- Capturing intelligence
- Eliminating high-value targets
- Rescuing hostages
- Sabotaging logistics
- Recovering downed pilots
- Designating landing zones
- Destroying bridges
- Planting surveillance devices

The direct firefight is only one part of the experience.

The strategic consequences are what make missions meaningful.

---

# Small Team. Big Impact.

This is the central philosophy of the project.

Three operators should be capable of changing the course of a regional battle.

Not because they kill hundreds of enemies.

Because they complete objectives that alter the battlefield.

Destroying a radar station may allow friendly helicopters to move.

Destroying logistics may weaken future enemy reinforcements.

Capturing intelligence may reveal entirely new operations.

One successful mission should influence many future missions.

---

# The War Exists Without You

The battlefield should never feel static.

Friendly forces fight.

Enemy forces reposition.

Supply lines move.

Aircraft patrol.

Convoys travel.

Territory changes.

Players are participating in a larger conflict rather than creating it.

The world should feel believable even when players are observing instead of fighting.

---

# Force Multipliers, Not Superheroes

Players should never feel overpowered.

Instead they should feel valuable.

The objective is not to clear entire enemy bases.

The objective is to create opportunities.

Examples:

Destroy the artillery battery.

Now friendly armor advances.

Destroy enemy radar.

Friendly aircraft begin flying.

Capture enemy communications.

New missions become available.

Destroy a bridge.

Enemy armor must reroute.

The player changes the battlefield instead of conquering it.

---

# The Evolution Rule

This project will evolve slowly.

Every iteration must improve the player experience.

If a feature is not fun today...

It is not ready.

No system exists simply because it will be useful later.

Every feature must immediately improve gameplay.

If adding complexity reduces enjoyment...

The complexity is removed.

Fun always comes first.

---

# Mods Before Code

Whenever possible:

Use existing systems.

Configure existing systems.

Extend existing systems.

Only build custom systems after existing tools can no longer accomplish the design goals.

We stand on the shoulders of the incredible Arma modding community.

Custom code exists to fill gaps—not reinvent solutions.

---

# Systems Over Missions

The project does not aim to create hundreds of handcrafted missions.

Instead it creates systems capable of producing thousands of unique experiences.

Examples:

Mission Director

Strategic AI Commander

Regional Alert System

Dynamic Logistics

Dynamic Patrols

Dynamic Reinforcements

Mission Chains

Weather

Persistence

Each system increases replayability instead of adding content that players eventually memorize.

---

# Scale Is A Design Constraint

The project must function at every player count.

3 Players

One special operations team.

6 Players

Two simultaneous teams.

12 Players

Multiple coordinated operations.

32 Players

Regional campaign.

64+ Players

Living public server.

The gameplay fantasy should never change.

Only the scale changes.

---

# Performance Is A Feature

A beautiful system that destroys server performance is a failed system.

Performance is considered part of gameplay.

Large numbers of AI should only exist when necessary.

Simulation should occur at multiple levels.

Strategic.

Dormant.

Active.

The server should simulate only what matters.

---

# Player Stories Come First

The project succeeds when players finish a mission and immediately begin telling stories.

Examples:

"Remember when we barely escaped the helicopter?"

"We accidentally triggered the armored QRF."

"We lost the convoy but still completed the mission."

"The radar strike changed everything."

Stories are the product.

Systems simply generate them.

---

# Design Principles

When making any decision ask:

Does this create memorable stories?

Does this increase replayability?

Does this improve immersion?

Is it fun immediately?

Will it still work with three players?

Will it still work with thirty?

If the answer is "no"...

Reconsider the design.

---

# Long-Term Vision

Eventually this framework should become a living battlefield where:

Enemy commanders adapt.

Friendly forces advance.

Supply matters.

Weather matters.

Reconnaissance matters.

Stealth matters.

Success matters.

Failure matters.

Every operation changes tomorrow's battlefield.

---

This project succeeds if:

Three friends cannot wait to play on Friday night.

Everything else is a bonus.
